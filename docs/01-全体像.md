# 全体像

この文書は、引き継いだ人が最初に読むためのものです。**どこに何があり、処理が
どう流れるか**を把握できることを目指しています。細かい仕様はコードとテストに
書いてあるので、ここでは構造と、そうした理由を残します。

## 何をする製品か

チェックリストと審査対象の書類を受け取り、**項目ごとに合否を判定**します。
判定にはその根拠（どの文書のどこを見たか）が付きます。

## 置き場所

| 場所 | 役割 | 言語 |
|---|---|---|
| `frontend/` | 画面 | TypeScript / React |
| `backend/` | API と、審査の段取り | TypeScript / Fastify / Prisma |
| `review-item-processor/` | **審査の中身**（モデルを呼ぶ、書類を読む） | Python |
| `cdk/` | インフラ定義 | TypeScript / AWS CDK |

`backend` と `review-item-processor` の分かれ方が要点です。**段取りは TypeScript、
判定そのものは Python** です。Python 側は DB に繋がず、S3 と Bedrock だけを見ます。

## 審査の流れ

Step Functions（`cdk/lib/constructs/review-processor.ts`）が段を並べます。

```
PrepareReview     審査するチェック項目を並べ、結果の入れ物を作る
   ↓
PlanReading       何を先に読むか決める（大きい書類・スキャンした書類だけ）
   ↓
ReadDocuments     区切って読む（Map。1回20ページ・画像20枚の上限があるため）
   ↓
StoreReading      読み取り結果を S3 にまとめる
   ↓
RecordReading     どこに何を書いたかを DB に残す
   ↓
ProcessAllItems   チェック項目ごとに審査（Map。ここが本体）
   ↓
FinalizeReview    集計して、ジョブを完了にする
```

各段が何をどう判定し、外れたときにどうするかは
[05-審査の流れ.md](05-審査の流れ.md) に基準値つきでまとめてあります。

### 読み取りは審査の補助

`PlanReading` から `RecordReading` までは**落ちても審査を続けます**。読めなくても
元のファイルを見に行けば判定はできるからです。各段に `addCatch` を置き、
`ProcessAllItems` へ進みます。

このとき **`resultPath` を捨てる**のが要点です。指定しないとエラーの中身が状態の
入力を丸ごと置き換え、次の段が必要とするデータが消えて実行ごと落ちます。
実際にそうなり、ジョブが「処理中」のまま止まる不具合になりました。

## 書類の読み方

審査のとき、書類は2つの経路のどちらかで渡ります（`review-item-processor/agent.py`）。

| 経路 | いつ | 中身 |
|---|---|---|
| **文書ブロック** | 1回の呼び出しに収まるとき | ファイルをそのまま Bedrock に渡す |
| **道具（tool）** | 収まらないとき、記入値や注釈があるとき | モデルが必要な箇所を読みに行く |

### Office ファイルは文章として渡す

Word・Excel・PowerPoint は Markdown に変換して渡しますが、**文書ブロックでは
渡せません**。3層すべてで断られます。

```
format="md"  + bytes → Bedrock が断る（引用ありは txt と pdf だけ）
format="txt" + bytes → Bedrock が断る（文字の形式は text で渡せ）
format="txt" + text  → Strands が落ちる（source.text を想定していない）
```

そのため変換した Markdown を、説明文と同じ**文章**として渡しています。
引用は Bedrock の citations ではなく、**モデルが JSON で返す citations 配列**を
読んでいる（`_extract_citations_text`）ので、この渡し方でも引用は残ります。

## 本文に出ないものを拾う

審査の質は「何を読めたか」で決まります。次のものは普通の文字抽出では出ません。

| 形式 | 拾っているもの | 実装 |
|---|---|---|
| PDF | 記入値（フォーム）、注釈・押印 | `pdf_extras.py` |
| Word | ヘッダー・フッター・コメント | `office_documents/word.py` |
| Excel | セルのコメント、数式 | `office_documents/excel.py` |
| PowerPoint | 図形の文字、回転、つながり | `office_documents/shapes.py` |
| Office 共通 | 埋め込み画像に写った文字 | `document_library.py` |

## データの持ち方

DB は MySQL（Aurora Serverless v2）、スキーマは `backend/prisma/schema.prisma`。

大きいものは DB に入れません。**書き起こした本文は S3**、DB が持つのは
**索引と状態**だけです。詳しくは [02-読み取り結果の持ち方.md](02-読み取り結果の持ち方.md)。
